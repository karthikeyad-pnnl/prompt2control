This block computes the enable command y1 for each piece of equipment in a plant based on the active stage index uSta, the equipment availability signals u1Ava, and — for plants that include lead/lag alternate equipment — the sorted runtime indices uIdxAltSor. It supports three plant configurations: non-hybrid plants, hybrid heat pump plants operating in single-operation mode, and hybrid heat pump plants operating in simultaneous heating-cooling mode.

Main equations

For each equipment item i, the enable command is determined as follows.

The staging matrix (or its transpose) encodes which equipment items are required at each stage. A row of the transpose matrix corresponding to equipment i is extracted at the active stage index via reqEquSta ( Buildings.Controls.OBC.CDL.Routing.RealExtractor). When the stage index is zero the extracted row is zeroed out by voiStaZer so that all equipment is commanded off.

From the extracted row, three Boolean conditions are derived for each equipment item i:

  • isReq: the staging row value equals exactly 1, meaning equipment i is required without a lead/lag alternate.
  • isReqPosAlt: the staging row value is greater than zero, meaning equipment i is required either directly or as a potential lead/lag alternate.
  • isNotReqNoAlt: the staging row value is less than 1, meaning equipment i is either not required or is only a candidate lead/lag alternate.

Equipment that is directly required (isReq is true) and available (u1Ava is true) is enabled via isReqAva.

For lead/lag alternate equipment, the number of alternates needed to satisfy the stage requirement is computed as:

nalt,req = nequ,sta − nreq

where nequ,sta is the total number of equipment required at the current stage (summed from the staging row via nEquStaRea and converted by nEquSta) and nreq is the count of equipment directly required without a lead/lag alternate (counted by nReq). The block Buildings.Templates.Plants.Controls.Utilities.TrueArrayConditional (truArrCon) then generates a Boolean array that marks the first nalt,req available lead/lag alternate equipment items according to the sorted runtime order supplied by uIdxAltSor. An alternate equipment item is enabled when it is a candidate (isReqPosAlt and isNotReqNoAlt), available (u1Ava), and selected by truArrCon; this combined condition is evaluated by isReqAltAva and isReqAltAvaNee.

The final enable command for each equipment item is the logical OR of the two paths:

y1i = isReqAvai or isReqAltAvaNeei

Assumptions and limitations

The enable commands are updated immediately on a stage change, on a change in the heating-cooling mode signal, or when the number of previously enabled and still available equipment items falls below the number required at the current stage. Between these trigger events the previously computed enable vector is held via the Buildings.Controls.OBC.CDL.Logical.Pre block (y1Pre) and the Buildings.Controls.OBC.CDL.Logical.Switch block (logSwi), which prevents unnecessary toggling of equipment commands when availability or runtime rankings change continuously.

The block assumes that the staging matrices are correctly sized and consistent with nSta and nEqu. It does not implement any time delay or proof-of-operation feedback.

Typical use and important parameters

The parameters staEqu, staEquSinMod, and staEquDouMod define which equipment items are required at each stage for non-hybrid, hybrid single-operation, and hybrid heating-cooling configurations respectively. A value of 1 in row s, column i of staEqu means equipment i is directly required at stage s. A value strictly between 0 and 1 indicates that equipment i is a lead/lag alternate candidate at stage s. A value of 0 means equipment i is not used at stage s. The corresponding transpose matrices traStaEqu, traStaEquSinMod, and traStaEquDouMod are used internally by Buildings.Controls.OBC.CDL.Routing.RealExtractor to extract the equipment requirement vector for the active stage.

Set have_HpShc = true when the block is deployed in a hybrid heat pump plant that can operate in simultaneous heating-cooling mode. In this case the block switches between traStaEquSinMod and traStaEquDouMod depending on the Boolean input u1HeaCoo. When have_HpShc = false the block always uses traStaEqu.

The parameter nEquAlt sets the number of lead/lag alternate equipment items and must match the length of the uIdxAltSor input vector.

Options

When is_pumApp = true the block is configured for a pump control module application. This flag may alter how the staging matrices are interpreted in the broader plant control template.

Dynamics

The block is event-driven. The enable switch condition (swiEna) is activated by any of the following events:

  • A change in the stage index uSta, detected by cha.
  • The number of previously enabled and still available equipment items becoming less than the number required at the current stage, evaluated by nEnaAvaPre and intLes.
  • A change in the heating-cooling mode signal u1HeaCoo, detected by cha1.

Outside these events the output y1 is held at its previous value using Buildings.Controls.OBC.CDL.Logical.Pre.

Implementation

For hybrid plants the transposed staging matrix is selected at run time by the Buildings.Controls.OBC.CDL.Reals.Switch block swiMod, which is driven by the element-wise replication of u1HeaCoo to the matrix dimensions via booScaRepCol and booVecRepRow. For non-hybrid plants the constant matrix conTraMatStaEqu is connected directly to reqEquSta.u.

To prevent index-out-of-range errors when uSta = 0 (plant off), the stage index passed to reqEquSta is clamped to a minimum of 1 by maxInt, while voiStaZer multiplies the extracted row by zero so that no equipment is commanded on.
